# filepath: docs/gate4_prep_checklist.txt
Gate 4: first tethered hover. Human pilot in the loop, agent never touches the
vehicle. Every [ ] below is operator-executed.

Gate 4 pass criteria (from the master plan): position hold within +/- 10 cm for
2 continuous minutes, zero EKF resets, no LIO degradation events in the log.

=========================== A. BLOCKERS ===========================
Verified from log_2 2026-09-14 parameters. Gate 4 cannot start until these are
fixed; each is a single parameter.

    RC channel map (log_3, 2026-09-14; RC_CHAN_CNT 8): RC1-4 sticks,
    RC5 = arm switch (RC_MAP_ARM_SW), RC6 = UNASSIGNED, RC7 = flight-mode
    switch (RC_MAP_FLTMODE), RC8 = Offboard switch (RC_MAP_OFFB_SW).
    RC5-8 MIN/MAX/TRIM are exactly 1000/2000/1500, i.e. defaults - check in QGC
    that the radio is calibrated and each switch position crosses PX4's
    thresholds.
[ ] KILL SWITCH: ASSIGNED 2026-10-13 (RC_MAP_KILL_SW 6), TEST OUTSTANDING.
    RC_KILLSWITCH_TH 0.750 = kill when RC6 is ABOVE ~1750 us; if the kill
    position sends the low end, set it to -0.750. RC6 calibration is still the
    default 1000/2000/1500, so confirm in QGC's Radio page that the kill
    position crosses the threshold. COM_KILL_DISARM 5 s: motors stop at once
    but the vehicle stays ARMED for 5 s, and releasing the switch inside that
    window lets the motors spin up again - hold the kill, or disarm.
    MAN_KILL_GEST_T -1 (stick gesture off).
    Test, props off: arm on RC5, kill on RC6 -> motors stop instantly; hold ->
    auto-disarm after 5 s; then repeat releasing at ~2 s to see the restart on
    the bench rather than in the air. Nothing else on this list matters
    without it.
[x] DONE 2026-10-13: RC7 ladder set - low Stabilized (slot 1), middle Altitude
    (slot 4), high Position (slot 6). Confirm each position in QGC on the bench.
    Original finding: POSITION MODE IS NOT ON THE SWITCH. COM_FLTMODE1 = 8 (Stabilized),
    COM_FLTMODE4 = 1 (Altitude), COM_FLTMODE6 = 4 (Hold); slots 2, 3, 5
    unassigned - the pattern of a 3-position switch on RC7, which reaches
    slots 1, 4 and 6. Position is mode 2 and on no slot, yet the gate is flown
    in POSITION. Put it on one of the three reachable slots (Hold in slot 6 is
    the natural one to replace: indoors it depends on the same position
    estimate as Position) and confirm each switch position on the bench.
[ ] GEOFENCE IS OFF. GF_ACTION = 0 (None), GF_MAX_HOR_DIST = 0,
    GF_MAX_VER_DIST = 0. Containment is the geofence's job, not the EV guard's
    (px4_odom_bridge_ev_guard_spec.md section 9.1). Size it with the test volume
    and set an action before flying.

[ ] FOREIGN AUTOPILOT ON THE RADIO LINK (log_4, 2026-10-13). The SiK radio on
    TELEM1 (MAV_0_CONFIG 101) is linked to a radio attached to a powered
    ArduPilot flight controller that ALSO uses system ID 1. Its pre-arm text
    ("3D Accel calibration needed", "Compass not calibrated", ...) lands in
    this vehicle's log, and with MAV_0_FORWARD 1 QGC's commands to system 1 can
    reach it. Find the far end and power it off, or give this radio pair its
    own NETID; if the radio is not used for this project, MAV_0_CONFIG 0.
    Do not fix it by changing MAV_SYS_ID casually: the AS2 platform config
    targets system 1 (platform_pixhawk.yaml target_system_id).
[ ] PX4's OWN pre-arm state: pre_flight_checks_pass false only because the
    transmitter was off (manual_control_signal_lost) and the safety button was
    not pressed (CBRK_IO_SAFETY 0). Accelerometer and compass are fine - the
    calibration messages came from the other autopilot.
[ ] LOGGING: SDLOG_MODE is 0 (armed only) - it reverted from the 1 set on
    2026-09-14. Set SDLOG_MODE 2 (boot until shutdown) for bench sessions so
    events before arming are captured.

=========================== C. ESTIMATOR SETUP ===========================
[ ] Gates 1-3 formally passed and their transcripts stored in docs/.
    (Gate 3: operator called PASS 2026-09-14.)
[ ] gate3_ekf2.params re-read back from the FC and diffed against the file

    = -0.047 and EKF2_RNG_POS_* survive the reboot.
[ ] YAW TEST (gate3 open item 2, never run): rotate 90 deg clockwise, confirm
    heading rises by ~pi/2 and settles. The one axis never directly exercised,

[ ] HEIGHT PATH DECIDED (gate3 open item 10, section 11). Inside the hover
    envelope (<5 m, <1 m/s) three things engage that no bench test exercised:
    conditional range aid, MPC_ALT_MODE 2 terrain hold, and the terrain
    estimator. Decided so far: EKF2_RNG_CTRL stays 1, because range is the only
    height source independent of LIO. MPC_ALT_MODE 2 is still an open choice -

    caused 28-35 cm excursions and a reset during motion (gate3 section 14).

    dead-reckons at once and PX4 falls back to Altitude. Before re-enabling:

[ ] Flow/range sanity: listener distance_sensor and listener optical_flow show

=========================== D. BEFORE THE FIRST SPIN ===========================
[ ] Vibration re-check WITH props at hover throttle on the tether: fly nothing,
    just spin at low throttle strapped down, pull the log, Flight Review
    vibration metrics in the green band. If not, LIO health under vibration must
    be re-verified (repeat Gate 2 checks with motors running).
[ ] MPC limits confirmed active: attempt aggressive stick input on the bench,
    observe setpoint clamps in the log. Current limits: MPC_XY_VEL_MAX 1.0,
    MPC_Z_VEL_MAX_UP/DN 0.5, MPC_TILTMAX_AIR 20 deg, MPC_THR_HOVER 0.62.
[ ] Recording policy in force: rosbag limited to /Odometry and
    /fmu/out/vehicle_odometry; PX4 .ulg logging enabled (that is the primary
    record). SDLOG_MODE 1, SDLOG_PROFILE 129 (or 131 if the EV motion test is
    being run in the same session).

=========================== E. DURING THE HOVER ===========================
[ ] Pilot's hand on the kill switch for the whole flight.
[ ] Watch /px4_odom_bridge/status. FORWARDING is healthy. STALE means no LIO
    sample for over 1 s, so EV has stopped reaching PX4 - land. BLOCKED means EV
    has stopped permanently and will not resume without a restart - land. Known PX4 response to EV loss: COM_POSCTL_NAVL = 0, so it
    falls back to Altitude/Manual, keeping height on baro and range. That
    fallback is why EKF2_RNG_CTRL stays 1.
[ ] Watch for EKF resets. The pass criterion is zero; the 2026-09-14 incident
    produced 123 reset_pos_to_vision events in one session.
[ ] Abort conditions, agreed before arming: any EKF reset, any BLOCKED guard,
    any unexpected climb (terrain hold), any LIO degradation message.
